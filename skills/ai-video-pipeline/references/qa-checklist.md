# 成片 QA 清单（v1.1：证据制）

> 顺序：先骨架，再一致性，再内容正确性，再细节。
> 骨架错了回 Blender；一致性/内容错了改白模·锚图·契约；**不要重抽整条**。
>
> 铁律：**每条"通过"后面必须能贴出一个文件路径。** 没有证据的"通过"等于没验。

## A. 提交前（硬门）

- [ ] `doctor.mjs` 的 blender / ffmpeg / ffprobe 全绿
- [ ] `seedance_doctor` 的 api-key / ark-endpoint 通过
- [ ] `contract-init.mjs --check` 通过（锚图存在、`must_show` 非空、cue 在时长内）
- [ ] `prep-shot.mjs` 退出码 0（无禁词、无参数错误），`prompts/<shot>.txt` 由它生成
- [ ] 本地白模 MP4 已 staging 成公网 URL（或已是 `asset://`）
- [ ] `seedance_preview_request` 的 `payload.content` 角色顺序正确
- [ ] `omni_reference_task_type=reference`（白模参考）
- [ ] `ratio`：参考模式 16:9 等；首尾帧/edit/extend 必须 `adaptive`
- [ ] `duration` 4–30 或 -1；不是 3 秒；edit 是 -1
- [ ] `requestBytes` 没有接近 64MB
- [ ] 真人脸合规：参考图是 AI 虚拟人像/预置数字人/授权 `asset://`
- [ ] 手部：不入画/遮挡/中近景；没有多人肢体接触
- [ ] 快速转身：已切镜或拆分

## B. 白模素材

- [ ] 首帧、尾帧构图可读
- [ ] `contact.png` 能看到走位/运镜变化
- [ ] 画面无轨迹线、坐标轴、网格线、相机锥体、文字/标签
- [ ] **主体在契约位置**：`must_show.at/size` 描述的主体，在白模里就在那个位置、那个占比
- [ ] 脚接地、比例合理、无明显穿模/浮空
- [ ] 时长/分辨率/fps 与 spec 一致（`qa-video.mjs`）

## C. 运动骨架

- [ ] 镜头顺序与白模一致
- [ ] 景别与白模一致（白模全身 → 输出不要裁头）
- [ ] 白模里没有的墙/窗/灯/靶架没有被模型自由发明
- [ ] 机位变化与白模一致
- [ ] 主体走位/方向与白模一致
- [ ] 节奏/快慢与白模一致
- [ ] 没有新增/删除镜头
- [ ] **没有镜内切镜/尾段换机位**：`qa-consistency` 布局相关系数 ≥ 0.22
- [ ] 没有把白模的灰色材质、轨迹线、坐标轴、相机锥体渲染进成片

> 任何一项失败：回 Blender 改白模，重新渲染、重新提交。不要靠改提示词"修复"骨架。

## D. 一致性（v1.1 新增，机器判)

- [ ] 技术参数逐镜一致（`qa-consistency` 表 1）
- [ ] 声画/动作落点偏差 ≤ 0.2s，或本镜本来就是后期配音（表 2）
- [ ] 跨镜调色在容差内：亮度 ±0.05、饱和度相对 ±25%（表 3）
- [ ] 相邻镜硬切亮度差 ≤ 0.08（表 3）
- [ ] 镜内无切镜（表 4）
- [ ] `must_show` 的裁剪证据里，主体真的出现在契约坐标上

## E. 身份与细节（目视）

- [ ] 脸型/五官/年龄稳定，没有换脸
- [ ] 发型/发色/发长稳定
- [ ] 服装/颜色/材质稳定
- [ ] 装备细节稳定（**护目镜尺寸、面罩包裹高度、挂件**——《靶场校准》翻车点）
- [ ] 体型/头身比稳定
- [ ] 同一画面没有双胞胎/分身/角色互换
- [ ] 手部：手指数量正确，无多指/少指/畸形/穿模；手不入画或遮挡
- [ ] 皮肤：真实肌理、毛孔/细纹/自然高光；无过度磨皮/蜡感/塑料感
- [ ] 眼睛：正常人眼，不发光
- [ ] **道具比例**：环外径/纸宽、环宽/外径是否与锚图一致（并排比对）
- [ ] 场景结构：灯位数量与位置、隔板高度、靶架样式是否与场景锚图一致
- [ ] 文字：无字幕/水印/乱码/logo 泄漏

## F. 内容正确性（v1.1 新增）

- [ ] 每个 `must_show` 都在画面里，位置与契约一致
- [ ] 物理方向正确：枪口延长线/视线/运动方向/命中点（如：准星中心与靶心共线）
- [ ] 只表现看得见的因果（没有"7 米外的新弹孔"这种不可见结果）
- [ ] 没有要求跨帧维持的状态被画崩（弹孔跳动、纸边变形、烟雾回溯）
- [ ] 镜头内部的"故事状态"前后一致（同一发子弹不会打两次、弹匣不会自己满）

## G. 动态与音频

- [ ] 没有果冻感/拖影/闪烁
- [ ] 没有脚滑/漂浮/穿地
- [ ] 没有肢体融合/多手多脚
- [ ] 没有背景扭曲/建筑融化
- [ ] 快速动作没有崩坏
- [ ] 口型与台词同步（如果有对白）
- [ ] 音频：人声/环境音/BGM 符合预期，无爆音/水声/杂音
- [ ] **声画落点**：枪声/命中声与画面动作同帧，偏差 ≤ 0.2s（`qa-consistency` 表 2）

## H. 技术参数

- [ ] 时长在 4–30 秒内，且与预期一致（±0.6s）
- [ ] 分辨率与预期一致（如 1280×720 / 1920×1080）
- [ ] fps 24（或预期值）
- [ ] 编码 H.264/HEVC，MP4/MOV 可播放
- [ ] 有/无音轨符合预期
- [ ] `qa-video.mjs` 报告 `ok: true`

## I. 结论格式（照抄，别改写）

```text
QA 结论：PASS / PARTIAL / FAIL
证据：qa/consistency-report.md（硬失败 N，警告 M）

骨架：PASS/FAIL —— 说明镜头/走位/机位
一致性：PASS/FAIL/PARTIAL —— 技术/声画/调色/镜内跳变，各附数值
内容正确性：PASS/FAIL —— must_show 是否到位、物理方向是否正确
身份/装备：PASS/FAIL/未验证 —— 附抽帧路径
手部：PASS/FAIL/未验证
材质/皮肤：PASS/FAIL/未验证
场景结构：PASS/FAIL/未验证
技术：PASS/FAIL

失败项：F<x> —— 症状 / 修哪一层 / 下次怎么验证
未验证项：...
下一步：重渲白模 / 改契约 / 局部 edit / 后期配音 / extend / 接受
```

`PASS` 的条件是：没有任何硬失败，且**没有未验证项**。有未验证项就写 `PARTIAL`，
不要为了让报告好看而写 `PASS`。
